# 客户端接管与管理入口加固

2026-11-10。目标为减少运营商和公共 Wi-Fi 获得的访问内容、DNS 查询及意外直连信息。不对 VPS 服务商隐藏信息，不提供网站匿名，也不承诺协议不可识别。用户选择不新增中继、费用或自行开发的恢复守护程序。

## 已实施的订阅策略

- 保留 VLESS + REALITY 与 Hysteria 2 + Brutal，手动选择。
- PROXY 分组移除 DIRECT；节点失效时海外请求失败，不自动转直连。
- 已知海外域名规则位于国内 IP 规则前，避免被后面的国内 IP 匹配改变路径。
- 默认及海外 DNS 经 PROXY 内的加密 DNS；国内 DNS 单独走直连 DoH，节点坏掉仍可解析国内域名。
- DNS 启动解析也使用验证过 IP 证书的 DoH 地址，取消继承的明文/非预期 fallback。
- 启用内核 IPv6 处理，配合 TUN 安装 IPv6 路由。不能仅关闭 Clash IPv6 开关就宣称系统 IPv6 被禁用。

国内服务直连是既定需求：它们的目标地址、时序仍可被本地网络观察；直连的国内 DNS 服务商也能看到提交给它的查询。规则分类可能有遗漏，新增敏感海外服务需要补充规则并验证。

## Mac 原生配置

官方 Clash Verge 系统服务经用户单独确认安装，并由用户在本机完成管理员认证。它用于原生 TUN，不是额外编写的恢复任务。

- TUN 开启，自动路由、自动识别物理出口开启。
- DNS 模式 native；UDP/TCP 53 导入内核 DNS。
- IPv6 开启，使 IPv6 路由一起进入 TUN。
- 系统代理关闭，主要依靠 TUN 接管，减少退出后残留本机代理端口的情况。
- DNS 覆写保持关闭，使用本项目订阅中的 DNS 设置；切换到其他订阅不在本次策略保证内。

发现并修正过实际旁路：关闭 Clash IPv6 后，系统仍有公网 IPv6，测试路由经物理网卡。开启内核 IPv6 后，公共 IPv6 路由进入 TUN；强制 IPv6 的测试请求返回的出口为 VPS。不能把“IPv6 开关关闭”写成防泄漏措施。

## 故障处理

| 状态 | 预期 |
| --- | --- |
| 正常 | 国内按规则直连，海外经所选节点 |
| 节点失效，内核仍活着 | 国内仍可用，海外报错 |
| 正常退出 | 原生清理代理、TUN 和 DNS，恢复普通网络 |
| 客户端或内核异常 | 优先原生恢复；失败时用户手动恢复 |
| 仅界面退出而内核仍工作 | 不能只凭窗口消失断定代理已停止 |

不增加独立监督程序；不承诺整体被强杀后必定自动恢复或一定弹出通知。恢复普通网络不保证原来需要代理的网站能够直连。

### Mac 手动恢复

1. 若 Clash 还能操作，先关闭 TUN 和系统代理，正常退出。不要只关闭窗口。
2. macOS 系统设置 → 网络 → 当前网络的详细信息 → 代理，清除指向已停止 Clash 本机端口的 HTTP/HTTPS/SOCKS 代理；不要删除其他软件配置。
3. 检查 DNS。清除本次 TUN 遗留的虚拟 DNS，恢复变更前的 DHCP 或原有自定义 DNS。不要把“清空所有 DNS”当作适用于所有人的恢复方式。
4. 检查默认路由与国内 HTTPS 是否恢复。如果系统仍残留异常，先重新启动/正常退出 Clash；必要时重启设备。不要批量删除其他 VPN 的 utun 网卡或系统路由。

本机原网络状态记录保存在项目忽略目录，仅供设备所有者查看，不进入 Git。

## 管理控制台与状态页

公网管理和状态入口已关闭，公网 HTTPS 只保留设备订阅。真实管理路径、账号和状态页密码仍由服务器受限访问文件保存。

在 Mac 终端运行并保持窗口打开：

```sh
ssh -N \
  -L 127.0.0.1:16969:127.0.0.1:16969 \
  -L 127.0.0.1:19100:127.0.0.1:19100 joysol
```

然后访问：

- 管理页面：访问文件中的 panel_url，即本机 16969 加原管理路径。
- 状态页面：本机 19100 根路径，继续使用原独立状态页认证。

浏览器到本机转发入口使用 HTTP，跨公网的内容由 SSH 加密；服务端包装入口只监听回环，不能公开暴露。私有 Nginx 包装继续提供登录限频、备份维护阻断和状态页认证，避免直接绕过原有保护。

恢复部署时要同时恢复私有 Nginx 包装和 runtime 端口，再检查公网管理 404、私有登录、状态页认证和维护阻断；不要因恢复旧配置而重新开放公网控制台。

## 验证与剩余事项

已验证：5 项合成回归测试、当前安装内核的配置校验、隔离坏节点下国内 200/海外失败且内核存活、实际 Mac TUN 下国内/海外连接、IPv6 路由与出口、两种节点分别的 YouTube HTTPS 204、正常退出时物理路由/原 DNS 恢复及重启后 TUN 再接管。退出测试经用户同意暂停相关应用后执行，短时只读采样已结束。

管理侧检查覆盖公网入口关闭、SSH 转发访问、私有管理员登录、状态页认证和备份维护阻断。监听状态不等于视频播放验收。

仍需小米实机更新订阅并开启 VPN 接管，检查私人 DNS、应用绕过、IPv6、Wi-Fi/流量切换及退出恢复；不能把 Mac 结果直接算作手机已通过。Mac 的浏览器 WebRTC、休眠和不同公共 Wi-Fi 下的全面回归，以及长期双设备视频播放仍需后续实际验收。

不增中继时，本地网络始终能看见设备直接连接 VPS 的 IP、端口、时序和流量大小。加密与 DNS 接管不能抹去这些连接元数据。

# 操作与恢复

## 登录与客户端

管理地址、状态页地址、管理员和状态页的独立密码、每台设备的订阅地址，只保存在服务器 `/home/panel/secrets/access.json`。通过已配置的 SSH 查看，禁止复制到 issue、公开文档或 Git 提交。控制台登录与状态页认证独立，修改一方密码不会同步另一方。

2026-11-11 按用户要求恢复公网 HTTPS 管理和状态入口，同时保留 SSH 隧道作为备用。控制台先使用原状态页账号密码通过外层认证，再使用原 3x-ui 管理员登录；状态页继续使用原认证。两层都是密码认证，不是双因素认证。地址以访问文件中的 panel_url/status_url 为准。保护措施、隧道命令、客户端接管和手动恢复步骤见 [加固与恢复说明](privacy-controls.md)。

Mac 与安卓各导入对应的独立订阅，新建配置，不覆盖已有服务。使用规则模式，确认国内直连、海外使用节点。先手动更新一次订阅和地理规则数据，保证离线缓存可用。节点故障时国内 DNS 与直连不依赖该节点。

Mac 现使用官方服务支持的 TUN，系统代理关闭，IPv4/IPv6 一并接管。安卓需通过其原生 VPN 接管并单独验收；正常退出恢复普通网络，异常退出时接受手动恢复。不要把单纯关闭 Clash IPv6 当作关闭系统 IPv6。

3x-ui 中以设备名管理凭据；设备名称不是硬件认证，凭据不可转发。泄露后同时重置节点凭据和订阅令牌，并确认旧配置无法继续连接。

## 服务检查

现已正式启用 Hysteria 2 + Brutal；客户端更新原订阅后选择 HY2-Brutal，备用 REALITY 保留。参数、订阅转换器与恢复步骤见 [Hysteria 2 部署记录](hysteria2.md)。

```sh
sudo docker compose -f /home/panel/local/compose.yml ps
sudo systemctl status nginx panel-status panel-clash-subscription --no-pager
sudo systemctl list-timers --all --no-pager
sudo journalctl -u panel-backup -u panel-renew --since today --no-pager
```

管理页面展示任务、证书和监听状态，不把端口存活当作实际视频播放通过。网页关闭、服务器宕机或 HTTPS 无法使用时不能通过本网站通知。

## 备份与下载

每月 1 日北京时间 04:00 自动生成 `backups/YYYY-MM-01/panel-backup.tar.gz` 和同名 `.sha256` 文件；初次部署有当天的初始备份。目录只允许授权维护账号访问，不提供公网下载，不自动提交 Git。

手动执行初始/当天备份：

```sh
sudo python3 /home/panel/scripts/backup.py --kind initial
```

同周期成功备份不会覆写。月度历史不自动删除；空间不足时停止生成并提示。下载前检查目录实际日期，通过 SSH/SFTP 下载压缩包和校验文件到 Mac，使用 `shasum -a 256` 与校验文件比较。Mac 文件也应限制访问权限。

备份含真实配置与设备凭据，普通压缩不提供加密保护。只有已下载并验证的副本才有异地恢复价值。

## 恢复

1. 将可信压缩包复制到新主机的受限临时目录，验证 SHA-256；检查归档条目，不接受绝对路径、路径穿越或意外符号链接。
2. 在隔离目录解包，读取 `manifest.json` 中的镜像版本/digest。
3. 停止目标面板，恢复数据库与本地配置，恢复原权限；不要在正在运行的数据库上覆盖文件。
4. 检查 SQLite `PRAGMA integrity_check`，恢复时不要启动两份共享同一数据库的面板。
5. 检查已撤销设备是否被旧快照重新启用；必要时重新撤销或轮换凭据。
6. 在同版本隔离环境验证登录及设备数据后再恢复生产。版本回退可能需要对应数据库，不能只换镜像。
7. 重建 systemd 定时器、日志轮转、防火墙及 IP 证书。证书和 GitHub 凭据不从此应用备份恢复；新 IP 需要更新订阅与节点地址。
8. 检查 HTTPS、国内分流、代理、任务与告警，完成后清理临时明文副本。

若归档包含本地 TCP 性能参数及模块加载文件，恢复时同时重建对应的系统配置。旧快照可能不包含这些后续调优材料；不要只恢复面板数据库就假定网络参数也已恢复。具体参数文件不在公开仓库保存。

服务器及同机备份都丢失且没有人工下载副本时，公开仓库无法恢复面板账号和设备配置，只能重新配置。

## 更新与公开仓库

固定上游发布版本，不自动升级镜像。更新前生成维护备份，检查迁移说明，在维护窗口实施；验证失败恢复匹配版本的数据库与配置。

公开提交采用白名单，只允许文档与通用脚本。`.gitignore` 不会取消已有跟踪：每次提交前检查暂存文件及差异，备份、真实配置和凭据不得提交。服务器不持有用于自动备份推送的 GitHub 凭据。

# VPS 服务部署开发记录

日期：2026-11-09。本文记录需求收敛、实现、排障、验证和本地清理过程；不包含服务器公网地址、管理路径、订阅链接、实际配置或密钥。

## 1. 任务背景

用户已经购买 VPS，并在 Mac 配置好 SSH 密钥连接。本次任务是在既有服务器上部署个人与少量固定亲友使用的代理服务、成熟管理面板，以及必要的备份和状态提示。

开发分为两个阶段：先多轮确认方案，获得明确实施授权后才连接和修改服务器。实施期间按阶段汇报，最终交付服务、公开运维代码和操作说明。

## 2. 需求如何收敛

| 主题 | 最终决定 |
| --- | --- |
| 网络环境 | 中国大陆电信家庭宽带、手机流量 |
| 首期设备 | MacBook Pro、小米手机；电视暂不纳入 |
| 客户端 | 沿用支持 Mihomo 的现有客户端，各设备独立订阅 |
| 常态负载 | 两台各播放三小时 1080p，必须满足 |
| 高峰负载 | 五台一小时，以三路 1080p、两路 720p 为目标，允许部分降画质 |
| 分流 | 国内直连、海外代理；节点坏了不能连带阻断国内访问 |
| 设备身份 | 按独立凭据登记设备，不按使用者分组，不等同于硬件认证 |
| 管理面板 | 使用 3x-ui，第一版接受原生统计，不从零开发设备控制台 |
| 管理入口 | 公网 IP + 免费受信任 HTTPS，无需域名 |
| 监测补充 | 轻量管理员状态页，页面打开且可访问时弹窗 |
| GitHub | 公开仓库，仅保存可公开代码、文档与合成测试 |
| 备份 | 每月一次，普通压缩包按日期保存在 VPS，不上传 GitHub |
| 异地副本 | 用户不定期自行下载到 Mac，不自动外传 |

方案早期曾讨论加密备份、云端备份分支和人工合并。用户后来明确取消这些安排，最终实现不包含备份加密密钥、自动 Git 提交/推送、自动 PR 或云端备份。这里记录这一变化是为了避免维护时重新引入已取消功能。

## 3. 初始环境与容量判断

初检确认 Ubuntu 24.04.1 LTS、KVM、4 vCPU、约 4GB 内存、40GB 虚拟磁盘，约 36GB 可用，无 Swap。仅 SSH 对外监听，目标项目目录为空，GitHub 仓库无提交。未发现需要迁移的已有应用。

套餐由用户确认：不限流量，上传峰值 30Mbps、下载峰值 40Mbps。视频回传主要受服务器上传限制。以每路 1080p 预留 5–8Mbps、720p 预留 2–4Mbps作为规划假设，常态约 10–16Mbps，高峰约 19–32Mbps，另有协议开销和突发。

因此硬件不是首要限制，高峰带宽及中国大陆晚高峰线路才是主要验收对象。上述估算不能当作固定视频码率、端到端带宽保证或实际播放通过。

## 4. 最终架构

```text
设备客户端 ── REALITY 加密连接 ── Xray ── 目标服务
                                      │
浏览器 ── HTTPS / 反向代理 ── 3x-ui ── SQLite
                     └── 管理员状态页（只读）

systemd 定时任务
  ├── 采集健康状态 → 脱敏 JSON → 状态页
  ├── 证书续期 → Nginx reload
  └── SQLite 一致性备份 → 本地 tar.gz
```

选用 3x-ui 3.11.0、配套 Xray 26.10.21；镜像以 digest 固定。代理采用 VLESS + REALITY + Vision。数据库使用 SQLite，不部署独立数据库服务。

3x-ui 容器使用主机网络，但面板、订阅和 Xray 内部管理接口显式绑定回环地址。公网仅提供规划的 SSH、证书验证、代理及 HTTPS 入口。不启用本次不需要的容器网络管理特权和面板内 IP 限制模块。

实际部署配置保存在服务器受限目录，不在本文或公开仓库复制。版本清单位于服务器本地，并随应用备份归档。

## 5. 分阶段实施

### A：准备检查

通过 SSH 读取操作系统、负载、内存、磁盘、端口、已有工具、目标目录和 Git 状态，核实时间同步。检查 SSH 密钥可用，确认不会覆盖现有服务。

查阅上游发布、Docker 安装、IP 证书、SQLite 备份及仓库权限资料。准备阶段明确不将运行配置或凭据上传公开仓库。

### B：基础环境

安装 Docker、Compose、Nginx、SQLite、Python 运行工具和兼容 IP 证书的 Certbot。系统包更新完成，保留既有 SSH 救援路径后设置防火墙。

先验证新密钥会话，再关闭 SSH 密码认证；未修改或删除用户 Mac 上的 SSH 私钥。保留 root 密钥管理能力，没有把“关闭密码登录”误写成“禁用所有 root 登录”。

补丁安装后提示需要重启。待配置完成、备份及恢复检查通过后，执行受控重启，启用更新后的内核；重启后重新验证连接和自启。

### C：代理、订阅与 HTTPS

从官方镜像启动固定版本面板。随机生成管理员密码、管理路径和每设备独立 UUID/订阅令牌，仅保存在服务器权限受限的访问文件和数据库中。

配置两份设备订阅，生成包含国内直连规则和 DNS 策略的 Mihomo 配置。Nginx 负责 HTTPS 入口和内部反向代理；管理与订阅分别处理认证，避免网页登录破坏客户端自动订阅。

IP 证书先在 staging 环境验证，再正式签发。免费证书有效期约六天，配置自动续期、配置检查及证书重新加载。未要求购买域名，也未通过跳过证书校验解决访问问题。

### D：客户端集成检查

调用 Mac 已安装的 Mihomo 核心，以独立临时目录、独立端口启动测试进程。不改动原客户端订阅，不改变系统代理，不覆盖用户原有服务。

复用现有地理规则数据完成配置语法检查；通过该独立进程请求海外和国内站点，核对出口和路由日志。

受控停止新代理服务后再次测试：国内请求仍成功，海外请求失败；随后恢复代理，确认可重新连接。这验证了基础分流行为，不代表所有应用、手机网络和视频场景均已验收。

### E：状态页、备份与恢复

状态页使用 Python 标准库 HTTP 服务，仅监听回环地址，由 Nginx HTTPS 和独立管理员认证保护。root 健康采集任务只输出脱敏结果，网页服务以非 root 用户运行。

状态项包括最近备份、证书到期、续期检查、容器与监听、剩余磁盘。浏览器每 30 秒刷新，有新告警时弹窗，未恢复告警持续显示。模拟续期失败验证过弹窗，之后恢复真实状态。网页不具备离线通知或独立故障监测能力。

备份使用 SQLite 一致性副本和显式配置清单，不直接复制正在写入的数据库，不递归打包整个项目，避免备份套备份。归档和校验文件写入日期目录，限制权限；归档内包含恢复需要的敏感数据，但不包含 GitHub 凭据或用户 Mac 私钥。

备份期间暂时阻止经 Nginx 进入的管理操作，代理流量不因此停止；已在途的管理操作不构成严格全系统事务，因此备份应安排在低活动时段。任务有锁、失败状态、重试和同周期幂等保护。

数据库完整性检查通过后，在无网络、无公网端口的独立容器中从备份启动面板，检查接口可用，再删除测试容器和临时恢复目录。

### F：重启和仓库交付

重启后验证新内核、SSH、Nginx、Docker、3x-ui、状态页和代理恢复。重新测试 HTTPS、管理员登录、设备订阅隔离和 YouTube 连接。

公开代码首次提交为 `52a7caf`，重启验证补充提交为 `3754b13`。服务器初始化本地 Git 仓库，与公开远程主分支建立跟踪；未向服务器配置备份推送凭据。提交时按文件白名单检查，没有跟踪运行配置、密钥、数据库或备份。

## 6. 排障与修正记录

| 问题 | 原因与修正 | 验证 |
| --- | --- | --- |
| 容器初始化命令未按预期执行 | 镜像入口脚本固定启动服务，没有透传提供的 CLI 参数；改为显式调用容器内二进制设置账号和监听 | 公网管理入口开放前替换临时生成凭据，最终登录验证成功 |
| SQLite upsert 失败 | settings 的 key 不具备所假设的 UNIQUE 约束；在离线初始化事务中按 key 删除再写入 | 设置生效，面板、订阅仅本机监听 |
| 原 REALITY 目标产生上游警告 | 重新选择并验证 TLS 1.3、HTTP/2 可用目标，更新配置与订阅 | 最终配置校验无该警告，实际连接成功 |
| Certbot 演练长时间等待 | renew 默认随机延迟超出预设任务超时 | 禁用命令内随机等待后，dry-run 和 deploy hook 通过 |
| Python 编译缓存写入受限 | Mac 自带 Python 试图在沙箱外写缓存 | 改用不写缓存的语法检查；运行与测试在服务器 Python 3.12 完成 |
| 备份测试出现文件句柄警告 | 校验摘要使用的文件未显式关闭 | 使用上下文管理器，重跑测试无警告 |
| 服务器 Git pull 无上游 | 初始化索引后未设置分支跟踪 | 设置远程主分支跟踪后 fast-forward 同步成功 |
| 本地 headless 浏览器启动失败 | 本机执行环境限制 | 改用可用的浏览器自动化环境验证真实页面与弹窗 |
| Mac 临时进程清理受沙箱限制 | 默认沙箱不允许进程枚举 | 经允许的权限升级识别并关闭本次独立测试进程，未关闭用户原客户端 |

这些修正均在完成最终验证前处理；不将中间失败写成最终已交付行为。

## 8. Mac 本地清理与保留

清理对象仅限本次创建的临时下载、上游源码副本、一次性部署与验证脚本、独立客户端配置、测试日志、测试浏览器配置和测试进程。临时目录位于系统临时区域，按已知路径清单删除，不泛删用户文件。

临时上游源码与脚本合计约 44.3MB（文件逻辑大小，实际磁盘释放量可能不同）。独立客户端进程已关闭，其临时订阅配置和日志已删除；测试浏览器启动失败留下的专用配置目录也已清理。其余已知临时脚本和源码也已移除，按已知路径清单复核无残留。

保留：

- Mac 本地项目源码和 Git 历史。
- 原实施方案及本开发文档。
- 用户现有 Clash 客户端、订阅、地理规则和系统代理设置。

## 9. 后续维护

操作、下载备份、恢复与更新步骤见 [operations.md](operations.md)。备份未加密，手动下载后应保护 Mac 上的副本。只有已经下载并校验的副本才提供异地恢复能力。

所有真实地址、账号和订阅继续只在服务器受限文件中读取。公开文档不复制这些内容，后续提交仍应检查文件清单与差异，不能仅依赖 `.gitignore`。

## 10. 后续变更：恢复 SSH 密码登录

用户随后明确要求恢复 SSH 密码连接。已备份原服务器 SSH 片段配置，开启密码认证，保留公钥认证；检查配置语法后仅 reload SSH，不改动现有密码、不更改 SSH 端口，也不关闭密钥连接。

同时检查控制台：公网 HTTPS 入口仍使用原规划端口，面板后端继续仅监听本机。后端端口不能当作公网管理入口；管理地址需包含原 HTTPS 端口和完整管理路径。服务、证书和页面响应均检查正常。具体访问地址继续只从服务器访问文件读取，不写入公开文档。

## 11. 后续变更：面板默认端口提醒

用户提供面板截图，显示仍使用默认后端端口的安全提醒，并要求更换端口、重启面板。检查确认旧端口只监听回环地址，没有直接暴露到公网；该提醒来自后端端口设置，不代表公网入口改变或已发生入侵。

实施前检查新端口空闲，保存数据库和配置回退副本；更新面板监听、Nginx 上游和本地运行参数，并重启面板容器、重新加载 Nginx。健康检查改为优先读取本地运行参数中的 `panel_port`，保留旧快照的缺省兼容性。公网 HTTPS 入口与设备凭据保持原样。

真实端口配置仍仅保存在服务器本地，不加入公开仓库。验证包括新后端回环监听、旧监听消失、HTTPS 页面和管理员登录，以及订阅与健康状态。面板与代理同容器，受控重启会短暂中断代理连接。

首次切换在反向代理 reload 后立即检查，遇到瞬时 502，触发自动回退。第二次加入后端与 HTTPS 就绪轮询及连续请求检查后完成；最终管理员登录、两份设备订阅和健康检查通过，旧默认端口停止监听，新后端端口未直接对公网开放。

## 12. 后续性能排查：拥塞控制与重传

代理测速出现严重低速后，建立独立实时测试脚本，保持配置一致，对照直连与 SSH 承载路径，并记录 TCP 重传和拥塞窗口。随后做 CUBIC → BBR → CUBIC → BBR 对照，确认明显改善来自拥塞控制变化，而不是单纯重启。结果、实施边界与复现方法见 [性能诊断记录](performance-diagnosis.md)。

## 13. 后续算法与 UDP 方案比较

按用户要求比较 BBR + FQ、Hybla 及隔离 Hysteria 2 的 BBR/Brutal 模式。处理了自动多队列编号、测速源限流造成的无效样本，并加入实际算法/队列校验和 HTTPS 首字节检查。FQ 没有稳定收益，Hybla 明显较慢；Hysteria 的下载略快、短请求响应较快，但没有部署为正式节点。结束时恢复 BBR + FQ-CoDel，移除所有临时服务、凭据与防火墙规则。结果与限制见 [进一步对照测试](algorithm-comparison.md)。

## 14. 正式启用 Hysteria 2 + Brutal

用户随后要求使用 Hysteria 2 + Brutal。核对所用上游版本后，采用面板原生入站，关联现有三台设备记录；开放 UDP 443，只读挂载自动续期证书，并保留 TCP REALITY。新增本机订阅转换器，为该版本面板未导出的带宽参数补充协商提示；实测发现需要固定上游公网 Host，否则原 REALITY 节点会生成 localhost，已修正并复验所有设备订阅。新增转换器自启动及健康检查，补充凭据隔离、错误凭据、重启和 Mac 下载验证。实施参数、结果、回退和恢复见 [正式部署记录](hysteria2.md)。
